# QuotaBar v0.2 — Spec Addendum

**Date:** 2026-07-12
**Status:** User-approved scope (3 features, priority order below)
**Base:** v0.1.5 (see 2026-07-11-quotabar-design.md; all v1 constraints remain)

## Feature 1: One-click sign-in refresh (Claude + Grok only)

When a provider card shows `token_expired`, render a **Refresh sign-in**
button next to the error line. Clicking it invokes a new Tauri command
`refresh_signin(kind)` which spawns the provider's own CLI once with a
trivial prompt — exactly the manual remediation — then triggers a quota
re-poll:

- claude → `cmd /C claude -p "hi" --max-turns 1` (verified 2026-07-12: refreshes `.credentials.json`, ~8h token)
- grok → `cmd /C grok -p "hi"` (verified 2026-07-12: refreshes `auth.json`, ~6h token)
- codex → **no button** (no local `codex` binary exists on this machine — Codex is driven internally by omp; its ChatGPT token lasts ~8 days and rarely expires). Error copy stays as-is.

Constraints: spawn with `CREATE_NO_WINDOW` (0x08000000), 120 s timeout,
non-zero exit or timeout → error surfaced on the button ("Refresh failed —
run the CLI manually"); button disabled with "Refreshing…" while pending;
QuotaBar still never touches credential files itself (the CLI does its own
refresh). Fixed argv only — no user input reaches the command line.

## Feature 2: Burn-rate ETA + low-quota notifications

- **ETA:** persist the last quota sample per provider+window to
  `%APPDATA%\quotabar\state.json` (`{kind: {window_label: {t, used}}}`,
  written after each successful poll, loaded at startup — required because
  on-demand mode samples sparsely). Pure function
  `exhaust_eta(prev_t, prev_used, curr_t, curr_used, now) -> Option<DateTime>`:
  linear rate; returns None when Δt < 60 s, Δt > 48 h, rate ≤ 0.01 %/min,
  or already ≥ 100%. Panel window line appends `· runs out ~14:32` only
  when ETA is earlier than that window's `resets_at`.
- **Notifications:** via tauri-plugin-notification. Edge-triggered on
  health transitions into amber or red (per provider, once per transition,
  tracked in shell state): title `QuotaBar`, body e.g.
  `Claude: 28% left (5h window), runs out ~14:32`. In on-demand mode
  notifications can only fire when a poll happens (startup / panel open /
  Refresh now) — documented limitation, no hidden background polling.

## Feature 3: DeepSeek as fourth provider

- Data source: **official documented API** `GET https://api.deepseek.com/user/balance`
  with `Authorization: Bearer <key>`. Key from env `DEEPSEEK_API_KEY`
  (User env verified present on this machine) with config fallback
  `deepseek_api_key`. Response (captured live 2026-07-12, values here synthetic):
  `{"is_available": true, "balance_infos": [{"currency":"CNY","total_balance":"42.50","granted_balance":"0.00","topped_up_balance":"42.50"}]}`
  — note: balances are STRINGS.
- Semantics (balance-based, not window-based): plan pill shows the balance
  (e.g. `¥42.50`; currency symbol from `currency`: CNY→¥, USD→$). One
  window labeled `Balance`: with config `deepseek_budget` (number, same
  currency) set → `used% = (1 - balance/budget) × 100` clamped 0-100;
  without budget → 0% used when `is_available`, 100% when not (i.e. green
  until DeepSeek says the account can't serve). `resets_at` None. No usage
  stats (usage: None — omp logs out of scope).
- Tray icon becomes FOUR bars (order: Claude, Codex, Grok, DeepSeek), bar
  geometry recomputed for 32px (4×6px bars, 2px gaps, 1px margins);
  tooltip gains `DeepSeek NN%`. Identity color: teal `#3aa981`.
- `enabled.deepseek` config flag, default true; missing key → NoCredentials
  (gray bar), consistent with other providers.
